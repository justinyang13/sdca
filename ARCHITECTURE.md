# SDCA ARCHITECTURE (TRD) — authored by Claude, binding for Qwen
Project: new website for San Diego Chinese Academy 聖地牙哥中華學苑 (non-profit, founded 1988, class site La Jolla Country Day School). Source of truth for content: research/wiki/ (read school-facts.md, features.md, content-model.md, navigation.md, pages/*.md, assets.md). Look: design/INSPIRATION.md + design/inspiration-mockup.webp (placeholders in the mockup are NOT facts).

## 1. Stack (decided; do not change)
- Node.js 26 (installed), **Express 5**, **EJS** server-rendered templates, **no React, no bundler, no TypeScript**. Plain modern CSS (custom properties, grid, clamp) in one design system; small vanilla JS (nav toggle, filter tabs, lightbox, form UX) as ES modules, progressive enhancement (site works without JS).
- DB: **SQLite via built-in `node:sqlite`** (DatabaseSync). File `data/sdca.db` (git-ignored). WAL mode, foreign keys on. No native-compiled deps. Allowed npm deps only: express, ejs, marked (markdown), sanitize-html, express-session + a SQLite-backed session store written by us (small), helmet, compression, express-rate-limit, multer (uploads), csrf via own double-submit token. Nothing else without asking Claude.
- Tests: `node --test` (built-in). Lint: none required. Each module has tests.
- Port 3000 (env PORT), bind 0.0.0.0. Demo is reached over Tailscale at http://100.86.110.0:3000 (also MagicDNS name). Run as a macOS launchd user agent `com.sdca.web` (KeepAlive) created by `scripts/install-service.sh`; logs in `logs/`.

## 2. Languages / i18n (Chinese is first-class)
- URL prefix per language: `/en/...` and `/zh/...` (zh = Traditional 繁體, `lang="zh-Hant"`). `/` redirects by cookie `lang`, else Accept-Language (zh* → /zh/, else /en/). Header language switcher (EN | 繁體) keeps the user on the equivalent page. `<link rel=alternate hreflang>` on every page.
- UI strings in `src/i18n/en.json`, `src/i18n/zh.json` (same keys; a test fails if keys differ). Content rows in SQLite have `_en` and `_zh` columns; if one language is empty show the other with a small "(English only / 僅提供中文)" note.
- Fonts: system CJK stacks only (no external font downloads): sans `-apple-system, "PingFang TC", "Noto Sans TC", "Microsoft JhengHei", "Segoe UI", system-ui, sans-serif`; display serif `"Noto Serif TC", "Songti TC", "PMingLiU", Georgia, serif`. Use `font-variant-east-asian`, line-height 1.8 for zh body, `word-break: keep-all` avoided for CJK (use `line-break: strict`). Test with real zh content: no tofu, no overflow.

## 3. Design system (premium, enterprise, clean — see design/INSPIRATION.md)
- Tokens in `public/css/tokens.css`: navy `#0B2545`, ink `#14213D`, red `#B3112A` (accent/CTA, from the shield's tradition), soft blue surfaces `#F3F7FC`, paper `#FFFFFF`, gold hairline `#C9A227` used sparingly, neutral grays; radius 12/20; soft layered shadows; 8-pt spacing scale; type scale with clamp(); max content width 1200px. Dark-mode not required. WCAG AA contrast, focus rings, skip link, reduced-motion respected, 44px touch targets, semantic landmarks.
- Components (each a partial in `views/partials/`): header (logo lockup, 7-item nav with dropdowns, search, language switch, red Donate button, mobile drawer), page hero/banner, section heading, card, feature icon tile (inline SVG icons, hand-drawn simple line icons), event row with date badge, announcement list with filter tabs, program card, staff/board card, sponsor grid, document list, alert/notice, breadcrumb, footer (navy, 4 columns: school, links, contact, follow), forms.
- Imagery rules: REAL photos for every picture of people (classroom, events, board/staff) taken from research/assets — chosen by viewing candidates with the vision tool; hero uses a genuine classroom photo with a navy gradient overlay. Non-people banners (skyline, temple roofs, lanterns, calligraphy brush, paper texture) may be generated locally with draw-things-cli per ~/.claude/CLAUDE.md (never any people/faces, never render with a person). Logo: see §6.
- Photos processed with macOS `sips` into `public/img/<name>-{480,960,1600}.jpg` (strip metadata where possible); templates use `srcset`, `loading=lazy`, width/height attributes (no layout shift), alt text in EN+ZH.

## 7. Admin (simple, secure)
`/admin` login (scrypt, rate-limited, session cookie httpOnly+SameSite=Lax, CSRF token on all POST). Roles admin/editor. CRUD screens for: announcements, events, pages, programs, people, sponsors, documents (file upload via multer, ≤25 MB, pdf/jpg/png/docx/xlsx only, content-type sniff), media items, settings, contact messages inbox (mark read/export CSV), subscribers (export CSV). Markdown editor textarea with live preview, EN/ZH side-by-side fields, publish toggle, image picker. First-run: `scripts/create-admin.js` prompts or reads ADMIN_USER/ADMIN_PASSWORD env; never commit credentials. All writes append to audit_log. All user HTML sanitized with sanitize-html; markdown via marked then sanitized.

## 8. Quality, security, performance
- helmet CSP (self + youtube-nocookie + google maps if used), HSTS off for demo http, rate limits on contact/login/search, honeypot + time-trap on contact form, email never exposed in HTML source (render via small obfuscation), no secrets in repo, `.env.example` only.
- Page weight: home < 600 KB transferred excluding video; LCP image preloaded; gzip/brotli via compression; static caching with hashed query `?v=`; Lighthouse targets (run if available) perf ≥ 90, a11y ≥ 95, SEO ≥ 95. SEO: unique title/description per page and language, canonical, hreflang, OpenGraph, JSON-LD (EducationalOrganization + Event), sitemap.xml.
- Contact form: validates, stores in SQLite; email sending is optional (SMTP env; if not configured, only stored + shown in admin).
- Registration/payment stay with the external portal (link out clearly). Donation: PayPal hosted button link retained (use the hosted_button_id found in research) plus check-by-mail info and tax-receipt note.
- Accessibility + Chinese rendering check at 375, 768, 1280 px using the browser tools in the QA phase.

## CONTENT PRESERVATION RULE (owner rule, 2026-10-05) — applies to EVERY phase and every future change
Presentation may be redesigned freely (layout, cards, galleries, typography), BUT for every old page its CONTENT AND ORDER MUST BE PRESERVED: all text (EN and ZH), all images/photos with their captions, all PDFs/links/embeds/forms, and the ORDER of sections/items as on the old page (e.g. the order of board members, staff, programs, announcements, sponsors, FAQs, list items, photo sequence). Nothing may be dropped, merged away, shortened or reordered. If something cannot be placed, add it to research/CONTENT-LEDGER.md under NEEDS OWNER REVIEW instead of silently omitting it. Every phase report must state how this rule was verified (content-audit + image-parity + order check). Add an ORDER CHECK to scripts/content-audit.js: for each old page, the sequence of its headings and of its content images/links must appear in the same relative order on the new page (report any inversions).
